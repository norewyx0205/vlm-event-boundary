# Phase 3H: Gap Versus Absolute Event Timing

## Material Passport

- Status: design decisions settled on 3 November 2026 (see Decisions). Not yet implemented;
  no GPU work scheduled. The design, contrasts and reading rules below are fixed before
  any Phase 3H material is rendered or any forward is run; results never edit this file.
- Question: is the Temporal-boundary advantage caused by the inter-event gap itself, or
  by the later absolute position / greater recency of Event 2 that the gap also produces?
- Scope: behaviour only (first-token A/B margins). No probes, patches or knockouts.
- Model, processor, prompt template, dtype and two-A10 runtime are inherited unchanged
  from the frozen rescue50 runtime (`analysis/phase3g/.../preparation.json`, `source_runtime`).

## Why

Every Level-5 full-feature video uses one fixed schedule (15 fps, 270 frames, 18 s;
`scripts/generate_ladder_dataset.py:get_timing`, start hold 30 frames, events 30 frames):

| Condition | Event 1 | Gap | Event 2 | Event 2 end → video end |
| --- | --- | --- | --- | --- |
| Low | 30–60 | 0 | 60–90 | 180 frames (12 s) |
| Temporal | 30–60 | 45 (3 s) | 105–135 | 135 frames (9 s) |

The Temporal condition therefore changes three things together: the gap, the absolute
onset of Event 2, and its recency relative to the end of the video. Moving distractors
with `motion_timing = near_targets` (half of all distractors in the local L5_full annotations) start
with their target event and move with it as well.

The only existing control (Phase 3B relocation, 5 October; `run_phase3b_relocation_control.py`)
shifted the whole Low sequence 45 frames later (gap 0, Event 2 at 105–135) for two bases,
archived layout only. Unpatched margins moved −2.02 → −2.83 (base 005, still wrong)
and −1.84 → +0.08 (base 011, now correct). This shows that timing alone can move the
margin; with n = 2 and the letter preference present, it cannot apportion the effect.

**Structural limit.** With fixed event durations, Event 2 onset = Event 1 onset + 30 + gap.
Event-1 position, gap and Event-2 position have two degrees of freedom. The design
can hold Event 2 fixed while changing the gap (Event 1 then moves), or hold the gap fixed
while moving Event 2. It cannot hold both events fixed. With the total duration fixed,
recency is collinear with Event-2 onset; the design does not separate onset from recency.

## Design

Five timing cells per base. Each one is rendered from the same base specification (objects,
paths, colours, distractor geometry, total duration); only the event schedule changes.

| Cell | Event 1 | Gap | Event 2 | Event 2 end → video end | Status |
| --- | --- | --- | --- | --- | --- |
| `low` | 30–60 | 0 | 60–90 | 180 | existing condition |
| `low_mid` | 60–90 | 0 | 90–120 | 150 | new |
| `low_late` | 75–105 | 0 | 105–135 | 135 | new (= relocation control) |
| `temporal_early` | 15–45 | 45 | 90–120 | 150 | new |
| `temporal` | 30–60 | 45 | 105–135 | 135 | existing condition |

All onsets are multiples of 15 frames (1 s). At the processor's default sampling (2 fps,
temporal patch 2), each temporal token covers 1 s, so event boundaries stay
token-aligned in every cell; the preflight must confirm this from the recorded sampled-frame
indices. Every cell keeps at least 1 s of static lead-in.

**Distractors: follow the generator.** `near_targets` distractors are re-timed by
`timed_distractors` from each cell's own schedule. The original Low/Temporal contrast was
built the same way. The order-reversal renders instead froze schedules at the source
cell's times; that alternative was considered and not chosen (Decisions, item 2).

### Planned contrasts (per base, layout-symmetric S)

Each cell is run in both A/B layouts (`archived`-style and `option_order_permuted`), and
the analysis uses `S = (M_correct-A + M_correct-B)/2` and `b = (M_correct-B − M_correct-A)/2`,
as in Phase 3F.

| Contrast | Definition | Isolates |
| --- | --- | --- |
| G105 | S(temporal) − S(low_late) | gap, Event 2 fixed at 105 |
| G90 | S(temporal_early) − S(low_mid) | gap, Event 2 fixed at 90 |
| T0 | S(low_late) − S(low) | Event-2 onset/recency 60 → 105, gap 0 |
| T45 | S(temporal) − S(temporal_early) | Event-2 onset/recency 90 → 105, gap 45 |
| Total | S(temporal) − S(low) | the original Temporal advantage |

`Total = G105 + T0` holds exactly, so the original advantage decomposes into a gap part
at late onset plus a timing part at zero gap. A second decomposition,
`Total = T45 + G90 + [S(low_mid) − S(low)]`, is a consistency check. b and answer counts
are reported for every cell; layout-specific margins are secondary.

### Cohorts

1. **Primary: 50 fresh, unselected bases.** These are generated by the Phase 3B rescue-pool
   generator settings (Level 5, full features) at new base IDs never used before. There is no
   screening or replacement; all five cells are rendered by one code path and one encoder.
   This is the population-level test, free of outcome selection.
2. **Secondary: the frozen 50 rescue bases.** This links to Phases 3D–3G. Existing Low and
   Temporal prompts are reused only after the native renders reproduce the archived videos
   exactly (decoded frames, matched encoder as in the direct-D materials) and replay the
   archived logits exactly. Selection caveat: Low was selected wrong and Temporal right,
   so any contrast against an existing cell is biased by regression to the mean. **G90 is
   the only selection-free contrast in this cohort**, because both of its cells are new.

### Pre-specified reading (primary cohort, 95% base bootstrap, 2,000 draws)

- Gap-dominant: G105 excludes 0, G105 ≥ ½·Total, and G90 has the same sign.
- Timing-dominant: T0 excludes 0 and G105 includes 0.
- Otherwise mixed or inconclusive; reported as such.

There are two primary contrasts (G105, T0) and no multiplicity correction; everything else
is descriptive. For reference, the unselected order-reversed videos gave a layout-invariant
Temporal advantage of +0.74 [0.47, 1.01] over 50 bases (SE ≈ 0.14). This cohort size should
resolve a G105 of roughly half that size, but not much smaller.

## Forwards And Gates

| Block | Forwards |
| --- | ---: |
| Primary: 50 bases × 5 cells × 2 layouts | 500 |
| Secondary: 50 rescue bases × 3 new cells × 2 layouts | 300 |
| Gates: native-render replay of existing Low/Temporal, 2 preflight rescue bases × 2 × 2 | 8 |
| Total | ≈ 808 |

Gates (all must pass before the full run; failures stop the run, they are not skipped):

1. Native reconstruction: rendering a rescue base's `low` and `temporal` schedules reproduces
   the archived videos (decoded-frame exact within one environment, matched encoder), and
   the forward reproduces the archived first-token logits.
2. Timing audit per new video: target motion only inside the scheduled frames (frame
   differencing), distractor windows as the generator rule implies, identical frame count.
3. Processor audit: identical visual-token count and prompt token IDs across the five cells
   of a base/layout; the sampled-frame indices and the Event-1/Event-2 temporal-token bins are recorded.
4. Two-base preflight (one per first-mover identity) on the full cell grid before the full run.

Wrong answers are kept. No video is re-rendered, replaced or screened because of its outcome.
The unattended lifecycle follows Phase 3F/3G: tmux, preflight then full, independent verify,
checksummed backup, e-mail, idle check, Pause. Resume stays manual.

## Decisions (settled 3 November 2026)

1. **Cohorts: both.** The primary analysis uses the fresh, unselected cohort; the rescue
   cohort is secondary. Fresh base IDs are 1001–1050. They are generated by
   `scripts/generate_phase3b_rescue_pool.py` with its default seed (42) and settings, in
   batches of five (start IDs 1001, 1006, …, 1046), as for the rescue pool. That gives the
   same per-batch seeding rule and alternating extra first mover. IDs 1–450 are already used
   (L5_full 1–30, rescue pool 31–450). No fresh base is screened or replaced.
2. **Distractors follow the generator.** `near_targets` distractors are re-timed from each
   cell's own schedule by `timed_distractors`. This matches how Low and Temporal were built.
3. **No recency arm.** Onset and recency remain collinear; this is stated as a limitation.
4. **Thesis placement: main SQ3 analysis.** The confound concerns the central research
   question, so the result is reported in SQ3 whichever reading applies, including
   "inconclusive".

Encoding: each fresh base's five cells are rendered and encoded in one environment, the VM.
Each rescue base's new cells use the encoder history of that base's archived videos, as in
the direct-D materials (six early bases locally, 44 on the VM).

## What It Cannot Show

- It does not separate Event-2 onset from recency (collinear at fixed duration), nor gap from
  Event-1 position (they trade off when Event 2 is held fixed).
- It is behavioural; it does not say how the gap is used internally.
- One model and one synthetic stimulus family; results do not transfer automatically.
